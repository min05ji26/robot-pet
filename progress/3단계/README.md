## 1. 표정 그리기 drawFace

OLED(SSD1306 128×64, I2C A4/A5)에 상태별 표정을 그린다. **표정 번호 = 상태 번호(0~5)** 라서 통신 규칙표는 그대로이고, 번호 안의 움직임은 아두이노가 알아서 한다. 눈·입 모양은 HW 시험 코드(`firmware/tests/servo_oled_test`의 `face()`) 기준.

| 상태 | 표정 | 움직임 |
|---|---|---|
| 0 대기 | 뜬 눈 + `∨` 입 | 3초마다 깜빡 |
| 0 대기, 10초 지남 | 감은 눈 + `z` | 잠 |
| 5 복귀 → 0 대기 | 웃는 눈 ^ ^ + 웃는 입 | 2초 웃고 깜빡임 시작 |
| 1 트리거감지 | 커진 눈 + 반짝 + `o` 입 | — |
| 2 반응 | 웃는 눈 ^ ^ + 웃는 입 | — |
| 3 탐색이동 / 4 회피 / 5 복귀 | 집중한 눈(위가 일자로 잘림) | 입 꼼지락 (0.25초) |

- `drawFace(번호)`: 상태가 바뀔 때 (LabVIEW 0x01·0x05 → handleCommand)
- `updateFace(millis())`: loop에서 계속 불러 시간에 맞는 그림을 고르고, **그림이 바뀔 때만** 다시 그림
- U8g2 `_1_` 페이지 버퍼(128바이트), I2C 400kHz로 그리는 시간을 줄임
- 노션 "대기(감은 눈)" → **깜빡이다가 10초 뒤 잠(감은 눈)** 으로 다듬음 (규칙표 변경 없음)

**확인**
- PC 시간 시험: 깜빡임·10초 잠·복귀→대기 2초 웃음·트리거→대기는 안 웃음·입 꼼지락·같은 그림이면 다시 안 그림 ✅
- Wokwi (`firmware/wokwi/face_test`): 대기 → 트리거 → 반응 → 탐색 → 회피 → 복귀 → 대기 순서로 확인 ✅
- Arduino IDE 컴파일: 저장 공간 12520바이트(**38%**), SRAM 866바이트(**42%**) ✅

## 2. 멜로디 playMelody

LabVIEW가 **0x03(D1 = 번호)** 을 보내면 부저(D12)로 곡을 틀고, **곡이 끝나면 0x84** 를 보낸다 (통신 규칙표: 0x03은 재생이 끝났을 때 0x84).

| 번호 | 곡 | 쓰는 상태 | 길이 |
|---|---|---|---|
| 0 | 멈춤 | — | — |
| 1 | 깸: 도-미-솔-도 올라감 (HW buzzer_test 음) | 트리거감지 | 0.75초 |
| 2 | 기쁨: 짧고 통통 튀는 음 | 반응 | 약 1.2초 |
| 3 | 잘 자: 도-솔-미-도 내려감 | 복귀 | 1.5초 |

- 음표 `{Hz, ms}`를 **PROGMEM(플래시)** 에 저장 → SRAM을 거의 안 씀
- `tone()`으로 기다리지 않고 재생 → 노래 중에도 패킷·거리·표정이 계속 돎
- 멜로디 번호 1~3은 우리가 정한 것 (규칙표엔 "멜로디 번호"만 있음) → 4단계 LabVIEW에서 사용

**확인**
- PC 시험: 0x84는 곡이 끝난 뒤(0.75초) / 음 순서 523·659·784·1047Hz / 0·없는 번호는 바로 0x84 / 재생 중 새 곡은 처음부터 / 쉼표 처리 ✅
- Wokwi 듣기 시험: `firmware/wokwi/melody_test`
- Arduino IDE 컴파일: 저장 공간 14262바이트(**44%**), SRAM 900바이트(**43%**) ✅

**트러블슈팅**: 음 이름을 `A5`로 지었더니 아두이노 아날로그 핀 이름 `A5`와 겹쳐 `conflicting declaration 'const uint16_t A5'` 컴파일 오류 → 음 이름 앞에 `NOTE_`를 붙여 해결

## 3. 자체 소음 블랭킹

로봇이 **자기가 내는 소리(모터·서보·부저)를 박수로 착각하지 않게**, 그 소리가 나는 동안 + 끝난 뒤 300ms는 마이크를 무시한다. 블랭킹을 하려면 박수 감지가 먼저 있어야 해서 **박수 감지(0x81)도 같이 넣었다.**

- 마이크 측정값(HW, 3.3V, 50ms 최댓값−최솟값): 조용 23~25 / 서보 55~91 / 모터 87~124 / 박수 300~600 → 임계값 **200**

**박수 감지**

| | |
|---|---|
| 측정 | A0를 50ms 동안 읽어 최댓값 − 최솟값 (HW mic_test 방식) |
| 판단 | 임계값(기본 200, 0x04로 변경)보다 크면 박수 |
| 전송 | 0x81, D1 = 소리 크기 ÷ 4 |
| 중복 방지 | 0.5초 안 같은 소리는 한 번만 |

**블랭킹**

| 소리 | 무시하는 시간 |
|---|---|
| 모터 | 도는 동안 + 멈춘 뒤 300ms |
| 서보 | 명령 뒤 0.5초(움직이는 시간) + 300ms |
| 부저 | 노래하는 동안 + 끝난 뒤 300ms |

- 50ms 구간 안에 한 번이라도 자기 소리가 있었으면 그 구간은 통째로 버림

**PC 시험 (13개 통과)**: 조용 → 없음 / 박수 500 → 0x81 한 번 / 0.5초 안 중복 무시 / 150 무시 / 모터 중 무시 / 모터 멈춤 0.2초 무시·0.4초 감지 / 서보 0.6초 무시·0.9초 감지 / 멜로디 중 무시 / 멜로디 끝 0.15초 무시·0.45초 감지 ✅

Arduino IDE 컴파일: 저장 공간 14768바이트(**45%**), SRAM 921바이트(**44%**) ✅

> 이동 중(모터 도는 중)에는 박수가 안 들림 → 13주차 "모터 도는 중 오검출 없음"에 대응

## 4. String 안 쓰기, SRAM 확인

| 시점 | SRAM |
|---|---|
| drawFace 추가 후 | 866 / 2048 바이트 (42%) |
| playMelody 추가 후 | 900 / 2048 바이트 (43%) |
| 박수 감지·블랭킹 추가 후 | 921 / 2048 바이트 (44%) |

| 확인 | 결과 |
|---|---|
| 코드에 `String` 사용 | 없음 ✅ |
| `Serial.print` 사용 | 없음 ✅ (통신 경로는 패킷 전용) |
| SRAM | 921 / 2048바이트 = **44%** ✅ (목표 75% 이하) |

- String을 안 쓰는 이유: 아두이노 `String`은 메모리를 잘게 쪼개 써서 오래 켜 두면 메모리가 부족해져 멈출 수 있다
- SRAM을 아낀 방법: 표정은 U8g2 `_1_` 페이지 버퍼(128바이트), 멜로디 음표는 PROGMEM(플래시)
